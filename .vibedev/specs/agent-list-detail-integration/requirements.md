# 代理列表与详情页面集成需求文档

## 简介

本功能旨在优化代理管理系统的用户体验，通过完善代理列表与详情页面之间的交互关系，为系统管理员、销售总监、销售组长和销售人员提供高效、流畅的代理管理体验。重点关注数据展示的一致性、导航体验的提升以及交互流程的优化。

## 需求列表

### 1. 导航与过渡

#### 1.1 列表到详情页面的跳转
**用户故事**: 作为系统用户，我希望能够从代理列表无缝跳转到详情页面，以便快速查看特定代理的详细信息。

**验收标准**:
1. 当用户在代理列表页面点击代理行的"更多"按钮时，系统应导航到该代理的详情页面。
2. 页面跳转应保持流畅，并显示过渡动画，提高用户体验。
3. 从列表到详情页的导航应保留用户的筛选条件和分页位置，便于返回后恢复之前的状态。

#### 1.2 详情页返回列表功能
**用户故事**: 作为系统用户，我希望能够从代理详情页面轻松返回代理列表，不丢失我之前的筛选和分页设置。

**验收标准**:
1. 详情页面应显示明确的"返回列表"按钮，位于页面顶部。
2. 当用户点击"返回"按钮时，系统应导航回代理列表页面。
3. 返回后应保持用户之前的筛选条件和列表位置。
4. 如果用户是通过直接URL访问详情页面，返回应导航到默认列表视图。

### 2. 数据一致性与状态管理

#### 2.1 数据同步
**用户故事**: 作为系统用户，我希望在详情页面编辑代理信息后，列表页面也能同步更新，以保持数据一致性。

**验收标准**:
1. 当用户在详情页面更新代理信息并保存时，系统应更新Pinia存储中的代理数据。
2. 当用户返回列表页面时，更新后的代理信息应反映在列表中，无需手动刷新。
3. 如果用户在详情页面删除代理，返回列表页面时该代理应从列表中移除。

#### 2.2 页面状态保存
**用户故事**: 作为系统用户，我希望系统能够记住我在列表页面的浏览位置和筛选条件，以便在返回时无需重新设置。

**验收标准**:
1. 系统应在Pinia存储中保存用户的筛选条件、排序设置和分页信息。
2. 当用户从详情页面返回列表页面时，系统应恢复保存的列表状态。
3. 状态保存应在会话期间有效，用户刷新页面后可选择性地清除。

### 3. 增强详情页面功能

#### 3.1 行动面板
**用户故事**: 作为管理员或销售总监，我希望在代理详情页面有便捷的操作按钮，以便快速执行常见操作。

**验收标准**:
1. 详情页面应包含固定的操作面板，包括"编辑"、"删除"、"刷新"等按钮。
2. 操作按钮应根据用户角色动态显示，仅显示用户有权执行的操作。
3. 操作面板应在页面滚动时保持可见，便于随时操作。

#### 3.2 数据可视化
**用户故事**: 作为系统用户，我希望在详情页面查看代理业绩数据的可视化图表，以便更直观地了解代理表现。

**验收标准**:
1. 详情页面应展示代理的业绩数据图表，包括有效客资数、成交金额和提成金额的趋势。
2. 图表应支持不同时间范围的筛选（例如：周、月、季度、年）。
3. 图表应具有响应式设计，适应不同屏幕大小。
4. 图表应包含必要的交互功能，如悬停查看详情、缩放等。

### 4. 交互优化

#### 4.1 实时数据加载
**用户故事**: 作为系统用户，我希望在浏览代理详情时能够看到实时更新的数据，而不必手动刷新页面。

**验收标准**:
1. 详情页面应实现数据的定期自动刷新机制（可配置的时间间隔）。
2. 数据加载过程应显示适当的加载指示器，而不阻塞界面操作。
3. 系统应优化API调用，避免不必要的请求和数据传输。

#### 4.2 响应式布局优化
**用户故事**: 作为系统用户，我希望代理详情页面在不同设备上都能有良好的显示效果，以便随时随地查看信息。

**验收标准**:
1. 详情页面应采用响应式设计，适应桌面端、平板和移动设备。
2. 在小屏设备上，页面应重新组织内容，保持关键信息的可访问性。
3. 页面的交互元素（如按钮、输入框）应针对触摸设备进行优化。

### 5. 权限控制

#### 5.1 按角色显示操作
**用户故事**: 作为系统管理员，我希望系统能根据用户角色智能显示或隐藏操作按钮，以确保安全和操作合规。

**验收标准**:
1. 系统应根据当前登录用户的角色动态控制详情页面的编辑、删除等操作按钮的可见性。
2. 只有系统管理员和销售总监可以查看和修改所有代理的详细信息。
3. 销售组长只能查看和编辑其组内的代理信息。
4. 销售人员只能查看代理的基本信息，不能执行编辑或删除操作。

#### 5.2 数据访问控制
**用户故事**: 作为系统管理员，我希望能够限制不同角色用户对代理详细信息的访问权限，保护敏感数据。

**验收标准**:
1. 系统应根据用户角色控制详情页面显示的数据字段。
2. 敏感信息（如佣金比例、绩效指标）只对有权限的用户可见。
3. 当用户尝试访问无权查看的代理详情时，系统应显示适当的权限错误消息。

## 技术约束

1. 所有前端组件必须使用Vue 3的Composition API和`<script setup>`语法。
2. UI组件必须使用项目中的shadcn-vue组件库，遵循项目设计规范。
3. 状态管理必须使用Pinia，确保页面间的数据一致性。
4. 路由管理使用Vue Router，支持动态路由和路由守卫。
5. 所有列表和详情页面的共享业务逻辑应封装为可复用的composables。
6. 必须实现完善的错误处理和加载状态管理。
